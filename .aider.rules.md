# Aider rules for this workspace

## Working agreement
- Prefer production-grade practices; no demo shortcuts unless explicitly requested.
- Suggest manual commands to run in Linux VM; do not assume automation.
- Keep changes minimal and scoped; avoid unrelated refactors.
- Do not add or remove comments/documentation unless requested.

## Architecture constraints
- Backend: FastAPI.
- Frontend: HTMX + server-side templates.
- Deployment: Docker (compose acceptable).
- CI: Jenkins.
- Single-tenant and privacy-first: no third-party telemetry by default.

## Security and privacy
- Never log secrets.
- Avoid storing raw IP addresses; if needed for abuse prevention, document truncation/hashing and retention.
- Default to least privilege (non-root containers, minimal ports exposed, narrow network access).
- Keep admin/debug endpoints protected (not publicly exposed).

## Code quality bar
- Add input validation at boundaries (FastAPI request models, query params).
- Use explicit error handling and user-safe error messages.
- Prefer deterministic builds (pinned dependencies, reproducible Docker layers).

## DevOps standards
- Use immutable image tags (git SHA) in CI/CD; avoid deploying `latest`.
- Document rollback steps.
- Ensure SQLite is mounted to a persistent volume; include backup/restore approach.
- Add health checks and graceful shutdown handling.

## When editing files
- Keep imports at the top of files.
- Match existing formatting and conventions.
- If making behavior changes, include a brief test/verification plan (commands to run).
